# iPhone → Ubuntu напрямую по USB

Скрипт `iphone_screen/usb_stream.py` запускает прямой видеопоток средствами
pymobiledevice3 11.19.3. Mac, Mac Bridge и DeviceKit не участвуют.
Это отдельный просмотр экрана; источник кадров и управление в `game_state.bot`
пока остаются прежними. На подключённом iPhone 17,1 с iOS 27.0 (24A5408d) проверено получение
скриншотов по USB. Служба видеопотока на этой конфигурации отсутствует.

## Подготовка

На iPhone включите **Настройки → Конфиденциальность и безопасность → Режим
разработчика**, выполните запрошенную перезагрузку. Подключите iPhone к Ubuntu
кабелем с передачей данных, разблокируйте экран и подтвердите «Доверять».
Не запускайте захват при работающей камере или микрофоне другого приложения.

На Ubuntu установите USB-службу и создайте отдельное окружение **из корня проекта**:

```bash
sudo apt install usbmuxd libimobiledevice-utils python3-venv
sudo systemctl start usbmuxd
python3 -m venv .venv-usb
.venv-usb/bin/python -m pip install -r iphone_screen/requirements-usb.txt
```

Окружение с моделями бота `venv` не изменяется. Сам скрипт запускайте без sudo.
Подготовка DDI может скачать образ разработчика с серверов Apple и занять время;
его монтирование выполняется перед проверкой/просмотром. Режим разработчика
скрипт сам не включает.

## Проверка и просмотр

```bash
.venv-usb/bin/python -m iphone_screen.usb_stream --check
.venv-usb/bin/python -m iphone_screen.usb_stream
```

После сообщения о готовности сервера откройте **http://127.0.0.1:8080/**.
Изображение идёт с iPhone по USB на этот ноутбук, браузер подключается к
локальному серверу. Сервер слушает только loopback. Просмотр использует HEVC
и требует поддержки этого кодека в WebCodecs браузера.

Если браузер Ubuntu не декодирует HEVC, используйте VNC: декодирование тогда
выполняется PyAV на ноутбуке, без зависимости от видеокодеков браузера.

```bash
.venv-usb/bin/python -m iphone_screen.usb_stream --viewer vnc
```

Подключите Remmina или другой VNC-клиент к **127.0.0.1:5901**.
Готовые web/VNC-просмотрщики библиотеки также могут передавать нажатия;
это не интеграция с управлением бота. Остановка сервера — Ctrl+C.

`--udid ID` выбирает конкретный USB-iPhone при нескольких подключённых
устройствах; скрипт не выбирает произвольное устройство в этой ситуации.
`--port 8081` меняет локальный порт. `--check` проверяет доступность службы,
но не доказывает, что поток уже декодируется: для этого откройте просмотрщик.

Если USB-устройство не найдено, проверьте кабель, доверие и службу:

```bash
systemctl status usbmuxd
idevice_id -l
```

Совместимость с конкретной сборкой iOS 26, частоту кадров и задержку необходимо
проверить на устройстве. Отсутствие Mac само по себе не гарантирует ускорения.

Исходники используемой версии:
- [Команды видеопотока](https://github.com/doronz88/pymobiledevice3/blob/v11.19.3/pymobiledevice3/cli/developer/core_device.py)
- [RSD-туннель](https://github.com/doronz88/pymobiledevice3/blob/v11.19.3/pymobiledevice3/remote/rsd_tunnel.py)

## Ошибка No such service: com.apple.coredevice.displayservice

Это означает, что служба отсутствует в RSD-списке устройства. До HEVC-декодера
запрос ещё не дошёл, поэтому смена браузера или переключение web → VNC
не исправляют эту ошибку. Само наличие iOS 26/27 и успешное монтирование DDI
не гарантируют доступность службы. Скрипт теперь проверяет её до запуска сервера
и выводит фактическую версию iOS; `--check` возвращает ненулевой код при её отсутствии.

Резервный способ получения изображения через доступную DVT-службу:

```bash
.venv-usb/bin/python -m pip install -r iphone_screen/requirements-usb.txt
.venv-usb/bin/python -m iphone_screen.usb_stream --viewer screenshots
```

Если зависимости уже установлены в `venv`, можно использовать `venv/bin/python`.
Откроется окно OpenCV, выход — Q/Esc или Ctrl+C. Кадры запрашиваются
последовательно, без накопления очереди и без сохранения на диск.
Это скриншоты, **не HEVC-видео**. На проверенном устройстве три запроса заняли
275, 154 и 154 мс (без учёта отображения); частота порядка 6 кадров/с является
только ориентиром. Подмена источника в боте автоматически не выполняется.

Отсутствие displayservice может зависеть от системы и DDI. Скрипт не удаляет
и не заменяет уже подключённый образ разработчика; причина отсутствия службы
на проверенном устройстве пока не установлена.
