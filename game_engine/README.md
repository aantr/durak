# Движок подкидного дурака

C++17 + pybind11. Два игрока, 36 карт, без переводов. Игрок `0` — бот,
`1` — соперник. Карты: `6C`…`AS`, где **C = ♣, D = ♦, H = ♥, S = ♠**.
Это канонические масти, не имена классов обученного детектора.

## Сборка

Из корня репозитория, тем же Python, которым запускается бот:

```bash
source venv/bin/activate
python -m pip install --no-build-isolation --no-deps ./game_engine
python -m unittest discover -s game_engine/tests -v
```

Нужны компилятор C++17, CMake, заголовки Python и установленные `pybind11`,
`scikit-build-core`. После изменения C++ повторите установку и перезапустите
Python-процесс. Изменять датасет или переобучать модели для движка не нужно.

## Бот с подсказками

```bash
python -m game_state.bot --suggest-moves --trump S --draw-detections
python -m game_state.bot --suggest-moves --trump S --trump-card 6S --mcts-ms 500
```

Козырь обязателен: текущий бот его не распознаёт. `--trump-card` задаёт точную
нижнюю карту колоды, если она известна. Без неё движок знает только её масть
и выбирает возможный козырь при каждой симуляции. Меняйте козырь при новой партии.
Подсказки выводятся в консоль, автоматических нажатий нет. Повторные одинаковые
состояния используют предыдущую подсказку. Поиск идёт в потоке обработки кадров
и освобождает Python GIL; OpenCV-интерфейс продолжает работать.

## Python API

```python
from game_engine import DurakEngine

engine = DurakEngine(
    trump="S", bottom_trump="6S", iterations=3000,
    time_limit_ms=250, seed=42,
)
result = engine.suggest(game_state)  # DurakGameState или state_snapshot(...)
if result["status"] == "ok":
    print(result["action"])
    # {'type': 'defend', 'card': '9H', 'target': 0, 'target_card': '8H'}
    print(result["moves"])  # все легальные варианты, visits и value
```

Действия: `attack` (ход/подкидывание), `defend` (отбой конкретной карты),
`take` (взять), `pass` (закончить подкидывать). `target` — индекс пары на столе,
`target_card` — карта атаки; это не экранные координаты. Каждый вызов выдаёт
одно следующее действие, после него нужен новый снимок состояния.

Для воспроизводимости используйте фиксированный `seed` и `time_limit_ms=0`:
тогда поиск ограничен только числом итераций. При положительном лимите времени
текущая симуляция завершается целиком, поэтому бюджет приблизительный.

## Правила

- Отбой старшей картой той же масти либо козырем против некозырной карты.
- Подкидывание по рангу любой карты стола, включая защитные.
- До шести атакующих карт, но не больше количества карт у защитника в начале
  розыгрыша. Специального ограничения первой атаки в пять карт нет.
- После `take` атакующий ещё может подкидывать до лимита; `pass` завершает взятие.
- Атакующий может закончить подкидывание до завершения отбоя. Защитник затем
  отбивает оставшиеся карты либо берёт.
- При успешном отбое стол уходит в биту, защитник становится атакующим.
  При взятии атакующий сохраняет ход.
- Добор до шести: сначала прежний атакующий, затем защитник. Открытый козырь
  забирается последним. Выход из игры проверяется после завершения розыгрыша
  и добора, а не сразу после выкладывания последней карты.
- Если после отбоя оба без карт и колода пуста, **побеждает атакующий**.
  Для другого варианта API поддерживает `simultaneous_winner="defender"`.

## Скрытые карты и MCTS

Поиск — single-observer information-set MCTS: новая допустимая раскладка
неизвестной руки и колоды на каждой итерации, общее дерево публичных действий,
UCT с учётом доступности действий в разных раскладках. На узлах соперника
полезность обращается. Известные карты соперника, бита и нижний козырь фиксируются;
случайные распределения остальных карт равновероятны при этих ограничениях.

После расширения дерева выполняется смешанная случайная/эвристическая симуляция
(предпочтение дешёвым картам и сохранению козырей). В конце партии награда равна
1 за победу бота и 0 за поражение. Если достигнут `rollout_depth` (по умолчанию 256),
используется оценка по разнице числа карт в руках. **`value` — средний балл
симуляций, а не калиброванная вероятность победы и не гарантия лучшего хода.**
`terminal_rollouts` и `cutoff_rollouts` показывают долю законченных симуляций.

История решений соперника пока не используется для изменения вероятностей
скрытых карт. Циклический розыгрыш может достигнуть ограничения глубины; это
обрезанная симуляция с оценкой, не игровая ничья.

## Требования к состоянию распознавания

Нужны своя рука, количество карт соперника/колоды, бита и пары стола
(`field_layout` с `covers`). Известные карты соперника необязательны. Все 36 карт
должны быть учтены: известные карты плюс количества скрытых. Дубликаты,
неотбитые карты без защитника, невозможный отбой и неполные связи стола отклоняются.

В `your_turn` и `throw_in` атакующий — бот; в `defend_or_take` — соперник.
В `ready`/`opponent_turn` возвращается `status="waiting"`. Для явной позиции
можно передать `attacker=0/1`, `turn=0/1`, `defender_start_count=N`, `taking=...`,
`attacker_passed=...` в `suggest()`/`observation_from_state()`.

При ошибках OCR `suggest()` выбрасывает `ValueError`; бот отображает причину
вместо подсказки. Во время `Bat` и после преждевременной очистки стола трекером
по `I take` рекомендация может быть недоступна до согласованного снимка. Движок
не выдумывает утраченные карты или пары стола. Текущее число карт соперника у
бота вычисляется по остальным зонам — ошибки биты могут искажать его даже при
формально правильной сумме 36.

## Полный симулятор без распознавания

```python
from game_engine import _native

game = _native.Game.new_game(seed=42)
while game.winner == -1:
    actions = game.legal_moves()
    game.apply(actions[0])  # вместо этого можно использовать свой алгоритм
    game.validate()
print(game.winner)  # 0 или 1
```

Для заданной полной позиции: `_native.Game({...})` с полями `hands` (две руки),
`deck` (первая карта добирается первой), `discard`, `table` (словарь attack/defense
для каждой пары), `trump`, `attacker`, `turn`, `attack_limit`, `taking`,
`attacker_passed`, `winner` (-1 для незавершённой игры). Все карты должны быть
перечислены ровно один раз. `snapshot()` возвращает эту структуру.

Низкоуровневый поиск: `_native.analyze(observation, ...)`. Наблюдение содержит
`hand`, `known_opponent`, `opponent_count`, `deck_count`, `discard`, `table`,
`trump`, `bottom_trump` и те же поля фазы. `_native.sample_world(observation, seed)`
позволяет проверить генерацию допустимого полного состояния.
