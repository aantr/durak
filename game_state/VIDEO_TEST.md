# Проверка состояния на видео

Из корня проекта:

```bash
venv/bin/python -m game_state.video_test recording.mp4 --fps 30 --draw-detections
venv/bin/python -m game_state.video_test recording.mp4 --fps 10 --no-window --output states.jsonl
```

Используются тот же `DurakGameState`, детекторы, нормализация и режим
`--slow-every 2`, что и в боте. Mine/opponent обрабатываются каждый выбранный
кадр, остальные — через кадр; смена надписи вызывает полный проход.
MCTS и отправка действий на телефон здесь не запускаются.

По умолчанию ожидание следующей выборки пропускается: часы видео сразу
переходят к следующему отсчёту, без `sleep`. Декодирование, распознавание и
передача результатов по-прежнему расходуют время видео. Например, если
обработка кадра на 0.0 с заняла 0.35 с при выборке 10 FPS, следующим будет
кадр около 0.3 с, а не 0.1 с. Если обработка заняла 0.01 с, выборка 0.1 с
начнётся сразу, без ожидания оставшихся 0.09 с. FPS задаёт сетку выборки
на временной шкале видео, а не ограничение скорости выполнения команды.

Сохраняются выборка по PTS, пропуски при медленном распознавании, порядок
обновлений состояния и отбрасывание результатов за концом временной шкалы.
При одинаковом времени обработки выбираются те же кадры; точное совпадение
между реальными запусками не гарантируется из-за колебаний скорости моделей
и планировщика ОС. Значения `finished_at` относятся к часам видео с учётом
пропущенных ожиданий, `recognition_ms` — к реальному времени распознавания.

Для прежнего воспроизведения по реальным часам:

```bash
venv/bin/python -m game_state.video_test recording.mp4 --realtime
```

Ускоренный проход завершается сразу по окончании виртуальной временной шкалы;
родитель забирает все отправленные результаты, включая последний.
В обоих режимах длительность исходного видео остаётся верхним пределом
реального рабочего времени: родитель останавливает незавершённый вызов GPU.
Последний начатый кадр может не дать результата. Распознавание каждого события
или последнего кадра не гарантируется: это имитация потока с пропусками,
а не исчерпывающий покадровый анализ.

Загрузка процесса/моделей и прогрев (2 обновления первого кадра по умолчанию)
выполняются **до отсчёта времени видео** и выводятся отдельно. История состояния
после прогрева сбрасывается. Полное время команды включает также завершение
процесса и запись итогов; оно не обязано укладываться в длительность ролика.
Рабочий интервал ограничен длительностью с точностью планировщика ОС, а не
жёсткими гарантиями real-time системы. `--warmup 0` включает загрузку моделей
в рабочий интервал, что может привести к пропуску начала или всего короткого видео.

Окно закрывается автоматически; Esc/Q — досрочный выход. С `--draw-detections`
показывается последний распознанный кадр. На быстрых проходах обновляются
mine/opponent, а рамки остальных детекторов сохраняются до их следующего
запуска. Если при новом распознавании объект не найден, его разметка исчезает.
Старые фрагменты изображения поверх текущего кадра не вставляются.
Консоль выводит состояние при изменении, JSONL сохраняет каждое
полученное состояние со счётчиком обработанных кадров, временем видео и длительностью распознавания.
Существующий файл журнала по умолчанию не перезаписывается. Для повторного
запуска укажите другое имя либо явно разрешите замену старого журнала:

```bash
venv/bin/python -m game_state.video_test recording.mp4 --output states.jsonl --overwrite
```

`--overwrite` удаляет прежнее содержимое журнала. Путь исходного видео
нельзя использовать как `--output`, даже с этим флагом.

По умолчанию нужны кадры 1206×2622, как в текущих настройках областей детекторов.
Для масштабированной записи того же интерфейса можно указать
`--resize 1206 2622`. Это растягивает весь кадр; чёрные поля, обрезку и другую
геометрию интерфейса нужно исправить отдельно. `--trump S` задаёт козырь вручную.

Навигация использует PyAV и реальные временные метки PTS, включая VFR-записи
и ненулевой start_time потока. Средний FPS служит только справочной информацией,
а не способом поиска кадра. Выбирается последний кадр, уже доступный на текущем
отсчёте видео; при паузах в VFR один и тот же кадр повторно не распознаётся.
Обычный EOF не является ошибкой. Длительность берётся из временной шкалы потока.
В метаданных JSONL `realtime` указывает выбранный режим.
В JSONL `video_time` — PTS относительно начала потока, `sample_time` — время
запрошенной выборки, `processed_frames` — счётчик выполненных распознаваний.
`frame_index` равен null: порядковый номер исходного VFR-кадра не вычисляется
из среднего FPS и не подменяется оценкой.
